# MarkMello Constitution

## Technology stack

### Platform
- .NET
- Avalonia UI
- Native AOT для production-сборок, где это применимо

### Target
- Desktop, cross-platform:
  - Windows
  - macOS
  - Linux

### UI model
- viewer-first desktop UI
- системная тема по умолчанию
- ручное переопределение темы пользователем
- минимальный chrome, фокус на документе

### Architecture baseline
- локальное desktop-приложение
- file-first сценарий открытия
- режим просмотра и режим редактирования разделены архитектурно
- editor stack загружается лениво, только по требованию

## Immutable principles

### 1. Viewer first
MarkMello в первую очередь является viewer’ом, а не editor’ом.

Любая новая функция должна оцениваться прежде всего по вопросу:
**не разрушает ли она сценарий быстрого чтения Markdown-файла?**

### 2. Instant open over feature richness
Скорость открытия важнее количества возможностей.

Если функция ухудшает cold start, first paint, time-to-readable-document или общее ощущение лёгкости, она не должна попадать в базовый путь запуска.

### 3. Document over interface
В центре внимания всегда документ, а не оболочка приложения.

UI должен быть минимальным, ненавязчивым и подчинённым контенту.

### 4. Edit mode must not tax view mode
Режим редактирования не должен ухудшать режим просмотра.

Это означает:
- editor components не инициализируются на старте viewer mode
- linting, hints, formatting toolbar, autocomplete и прочие editor-specific части не участвуют в initial render
- split layout появляется только после явного входа в Edit

### 5. Local-first and file-first
Приложение работает вокруг локальных файлов и прямого открытия документов.

MarkMello не требует workspace, проекта, облачного аккаунта, базы знаний или специальной структуры данных для базового сценария.

### 6. Fast path must stay simple
Путь “открыть файл → увидеть документ” должен оставаться самым коротким и самым дешёвым по вычислениям.

В этот путь не допускается включать:
- тяжёлую инициализацию editor engine
- второстепенные панели
- сложные фоновые процессы
- индексирование коллекций файлов
- функции, не нужные для чтения текущего документа

### 7. Progressive enhancement
Дополнительные возможности наслаиваются поверх базового быстрого просмотра, а не встраиваются в него как обязательная часть.

Сначала:
- окно
- тема
- документ

Потом:
- вторичные controls
- пользовательские настройки
- edit mode
- расширенные функции

### 8. Predictable desktop behavior
Приложение должно вести себя как хороший desktop-инструмент, а не как упрощённый браузерный контейнер.

Это включает:
- корректное открытие файлов по ассоциации
- понятные системные диалоги
- естественные хоткеи
- ожидаемое поведение окна, прокрутки, выбора темы и шрифтов

### 9. Cross-platform without platform denial
Кроссплатформенность обязательна, но без отрицания различий платформ.

Общая архитектура и поведение едины, но интеграция с ОС должна уважать платформенные нормы там, где это повышает качество UX.

### 10. Minimalism is a product rule, not just a visual style
Минимализм — это не только внешний вид, но и ограничение объёма продукта.

MarkMello не должен постепенно превращаться в:
- IDE
- docs workspace
- note-taking suite
- универсальный редактор всего текста

### 11. Measured performance, not assumed performance
Решения по производительности принимаются на основе измерений.

Ключевые метрики должны измеряться, а не оцениваться “на глаз”:
- startup time
- time to first window
- time to readable document
- memory usage in viewer mode
- memory usage after entering edit mode

### 12. Accessibility and readability are first-class concerns
Читаемость и доступность не являются второстепенными качествами.

Настройки отображения должны улучшать чтение, а не превращать приложение в перегруженный кастомизатор.
