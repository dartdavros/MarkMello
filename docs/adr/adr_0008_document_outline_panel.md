# ADR-0008: Document outline panel

## Status

Proposed

## Date

2026-10-23

## Context

В длинном документе MarkMello сейчас даёт две формы навигации: прокрутку и миникарту. Миникарта показывает форму документа, но не его структуру. Чтобы перейти к нужному разделу, приходится листать или искать текст.

Документ уже разобран в `RenderedMarkdownDocument`. Каждый `MarkdownHeadingBlock` несёт уровень, текст и `SourceSpan`. Viewer умеет прокручивать к заголовку по якорю (`TryScrollToHeadingAnchor`, `MarkdownHeadingAnchorSlugger`). Edit mode умеет сопоставлять строку исходника и позицию в превью. То есть данные и механизмы навигации уже есть, не хватает только поверхности, которая их показывает.

ADR-0006 исключал «workspace outline», то есть оглавление по всей папке. Это решение его не затрагивает: оглавление строится только для открытого документа и не обходит файлы папки.

Что остаётся обязательным:

- MarkMello — viewer-first;
- fast path `open file -> readable document` не должен дорожать;
- document surface остаётся главным визуальным центром;
- editor subsystem остаётся ленивой.

## Decision

MarkMello получает **панель оглавления**: дерево заголовков текущего документа в отдельной колонке главного окна. Панель опциональная, выключена по умолчанию и работает одинаково в viewer и в edit mode.

## Rules

### 1. Панель выключена по умолчанию, состояние запоминается

При первом запуске панели нет. Пользователь включает её явно, и видимость сохраняется в настройках. Пока панель выключена, её view, view-model и модель оглавления не создаются, и fast path не меняется.

### 2. Одна панель на уровне окна

Панель — колонка `MainWindow`, а не часть `ViewerView` или `EditWorkspaceView`. При переключении viewer ↔ edit она не пересоздаётся и не теряет прокрутку.

### 3. Сторона выбирается пользователем

Панель может стоять слева или справа от документа.

- Если открыта папка и оглавление слева, порядок колонок такой: `файлы | оглавление | документ`.
- Если оглавление справа, миникарта скрыта, пока панель видима. Если оглавление слева или выключено, миникарта ведёт себя как раньше.

### 4. Включение

- Кнопка третьей в плавающей группе слева вверху, рядом с кнопками меню и сайдбара.
- Горячая клавиша `Ctrl+Shift+B` / `Cmd+Shift+B`, парная к `Ctrl+B` (сайдбар). `Ctrl+Shift+O` уже занята.

### 5. Содержимое и вид

- Шапка: надпись «Оглавление» / «Outline» в стиле `mm-sidebar-root`.
- Дерево заголовков в визуальном языке сайдбара: те же отступы уровней, hover, selection, шевроны, виртуализация.
- Показываются уровни до `MaxLevel`, по умолчанию H1–H3.
- Пропущенный уровень (H1 → H3) не создаёт пустых промежуточных узлов: H3 становится дочерним ближайшего заголовка уровнем выше.
- Длинный заголовок обрезается многоточием в одну строку, полный текст показывается в tooltip.
- Inline-разметка в тексте пункта не рендерится, показывается plain text.
- Документ без заголовков (в пределах `MaxLevel`): панель остаётся на месте, внутри приглушённая надпись «В документе нет заголовков» / «No headings in this document».

### 6. Навигация

- **Viewer:** клик прокручивает документ к заголовку. Пункт находится по строке исходника (`SourceSpan.StartLine`), а не по якорю: так viewer и редактор используют один и тот же идентификатор, а слагификация не дублируется. Прокрутка идёт тем же способом, что и у якорных ссылок (`TryScrollTargetIntoView`).
- **Edit mode:** клик ставит курсор в начало строки заголовка (`SourceSpan.StartLine`), прокручивает редактор через существующий переход поиска по тексту (строка оказывается на уровне якоря синхронизации прокрутки, около 38% высоты окна редактора, а не у самого верхнего края) и переводит фокус в редактор. Превью подтягивается через существующую синхронизацию прокрутки.

### 7. Текущий раздел подсвечивается

- Viewer: по позиции прокрутки, текущим считается последний заголовок выше верхней границы видимой области.
- Edit mode: по строке курсора.
- Если текущий пункт внутри свёрнутой ветки, подсвечивается ближайший видимый предок.
- Подсветка — тем же способом, которым сайдбар выделяет открытый файл: акцентная планка 2 px слева (`mm-tree-active-bar`) и вес Medium. Фон `MmSurfaceHoverBrush` остаётся только для hover.

### 8. Сворачивание веток

Ветки сворачиваются шевроном. Состояние живёт, пока открыт документ, и не сохраняется между запусками. Свёрнутость хранится отдельно для каждого документа (вкладки), по ключу пункта `Уровень:Текст#n`, где `n` — порядковый номер одинаковых заголовков, поэтому одинаковые заголовки сворачиваются независимо. Запоминаются только действия пользователя, а не расстановка состояния при перестроении. Если после правки набор заголовков (уровень и текст) не изменился, дерево обновляется на месте (меняются только номера строк): панель не теряет прокрутку и не пересоздаёт пункты.

### 9. Вкладки

У каждой вкладки своё оглавление, но настройки панели (видимость, сторона, ширина, типографика) общие для окна.

### 10. Обновление в edit mode

Оглавление перестраивается из того же `RenderedMarkdownDocument`, что и превью, после того же debounce. Отдельного разбора исходника нет.

### 11. Настройки

Раздел «Оглавление» / «Outline» в окне «Расширенные настройки» (`AdvancedReadingSettingsWindow`), отдельным блоком `OutlineSettingsView`:

| Настройка | Значения | По умолчанию |
|---|---|---|
| Сторона | слева / справа | слева |
| Показывать до уровня | H1…H6 | H3 |
| Межстрочный интервал | 1.2–2.0, шаг 0.1 | 1.5 |
| Размеры по уровням (раскрываемый блок) | H1…H6, каждый 11–20 px | H1 15, H2 14, H3–H6 13 |

Размеры задаются в пикселях и не зависят от `InterfaceFontSize`. Межстрочный интервал один для всех уровней. Строки размеров для уровней глубже `MaxLevel` остаются редактируемыми, но приглушены.

### 12. Ширина

Граница панели перетаскивается мышью (`GridSplitter`) в пределах 220–600 px, по умолчанию 260 px. Диапазон шире, чем у сайдбара файлов (220–340), потому что заголовки документов бывают длинными; при нехватке места действует минимум 320 px для документа. Ширина сохраняется после отпускания мыши и хранится отдельно от ширины сайдбара.

Вид и поведение границы — как у сайдбара (`mm-sidebar-splitter`): невидимая зона захвата 8 px поверх 1-px границы, курсор `SizeWestEast`, при наведении и во время перетаскивания граница окрашивается `MmAccentBrush`. Когда панель справа, перетаскивается её левая граница, и тянуть влево — значит расширять.

## Architecture impact

### Domain

- `DocumentOutline`, `OutlineItem(Level, Text, SourceLine, Children)`.
- `DocumentOutlineBuilder`: чистая функция `RenderedMarkdownDocument → DocumentOutline`. Якоря через ту же логику слагификации и дедупликации, что и в viewer.
- `OutlinePreferences(IsVisible, Side, MaxLevel, LineHeight, LevelFontSizes, Width)` с `Default` и `Normalize` по образцу `ReadingPreferences`.
- `OutlinePanelSide { Left, Right }`.

### Application

Без изменений.

### Infrastructure

- `SettingsFileModel` получает `OutlinePreferences? Outline = null`. Старые файлы настроек читаются без ошибок и получают значения по умолчанию.
- Регистрация новых типов в `MarkMelloJsonSerializerContext` (AOT).

### Presentation

- `OutlineViewModel`, `OutlineItemViewModel`.
- `ShellViewModel.Outline.cs`: видимость, сторона, команда переключения, связь с активной вкладкой.
- `OutlinePanelView.axaml`, `OutlineSettingsView.axaml`.
- Навигационный контракт: viewer и editor реализуют переход к пункту и сообщают текущий раздел. Панель не знает, какой режим активен.
- `MainWindow.axaml`: колонки под панель слева и справа. Разметку колонок вынести так, чтобы файл не рос.
- Локализация RU/EN в `LocalizationService`.

## Rejected alternatives

### A. Отдельные панели в `ViewerView` и `EditWorkspaceView`

Два места размещения и синхронизация настроек. В edit mode третья колонка сжимает и редактор, и превью.

### B. Плавающая панель поверх документа, как миникарта

Перекрывает текст, ширина не меняется, визуально чужая рядом с сайдбаром.

### C. Вкладка «Оглавление» внутри сайдбара

Сайдбар существует только в folder mode (ADR-0007 Rule 3). Для одиночного файла оглавления бы не было.

### D. Размеры шрифта через «базу + шаг»

Компактнее, но не даёт точечно поправить уровень. Выбраны шесть явных значений в раскрываемом блоке.

## Consequences

### Positive

- Быстрая навигация по структуре длинных документов в обоих режимах.
- Переиспользуются существующие модель документа, якоря и синхронизация прокрутки.
- Пока панель выключена, приложение работает как раньше.

### Neutral

- Миникарта скрывается, пока панель справа.
- Новые строки локализации и новый блок в «Расширенных настройках».

### Negative

- `MainWindow` получает ещё одну колонку и связанную с ней логику.
- Подсветка текущего раздела требует отслеживать прокрутку и курсор.

## Implementation sequence

1. Domain: модель оглавления, builder, `OutlinePreferences` с нормализацией. Тесты.
2. Infrastructure: сохранение настроек и совместимость со старыми файлами. Тест.
3. Presentation: панель в viewer mode (колонка, splitter, кнопка, горячая клавиша, клик, пустое состояние).
4. Подсветка текущего раздела и сворачивание.
5. Edit mode: переход к строке, подсветка по курсору, перестроение после debounce.
6. Блок настроек в «Расширенных настройках», локализация.
7. Миникарта при правой стороне, ручная проверка: светлая и тёмная тема, обе стороны, folder mode, вкладки.

## Final statement

Оглавление — опциональная навигационная поверхность для текущего документа. Оно не трогает fast path, не индексирует папки и не превращает MarkMello в workspace-инструмент.

## Implementation notes and open points

Что выяснилось при реализации и осталось открытым.

- **Подчёркнутые (setext) заголовки.** Markdig указывает в `Line` строку подчёркивания, а не строку текста. В рендерере (`MarkdigMarkdownDocumentRenderer.SourceSpans.cs`) начало такого заголовка теперь считается как `Line` минус число переводов строки внутри span, иначе курсор в редакторе вставал бы на `-----`.
- **Пока панель выключена**, оглавление не строится, а viewer и редактор не вычисляют «текущую строку» при прокрутке и движении курсора: значение считается по запросу, когда панель подключается.
- **Колонки.** Левая панель оглавления лежит во вложенной сетке `OutlineLeftLayout` внутри колонки документа. Иначе граница панели файлов (`GridSplitter` с `PreviousAndNext`) парилась бы по индексу с колонкой оглавления, а не с колонкой документа, и не растягивалась бы вправо, пока оглавление выключено.
- **Решено (владелец, 2026-10-23): узкое окно.** Пока оглавление включено, колонка документа не уже 320 px: границы нельзя дотянуть так, чтобы документ исчез. При выключенном оглавлении раскладка не меняется. В самом узком окне правая панель может частично уйти за край.
- **Решено (владелец, 2026-10-23): папка и кнопка, остаётся как есть.** При открытой папке гамбургер живёт в шапке сайдбара, поэтому плавающая группа раньше не показывалась. Теперь в этом режиме над документом слева вверху висит одна кнопка оглавления. Место кнопки в режиме папки в макете не определено.
- **Решено (владелец, 2026-10-23): редактор, остаётся как есть.** Кнопки оглавления в режиме редактирования нет (плавающая группа в нём скрыта), панель включается горячей клавишей.
- Отступ вложенности дерева взят из существующего `TreeLevelIndentConverter` (12 px на уровень), макет показывал около 20 px.
