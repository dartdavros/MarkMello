# ADR-0007: Folder workspace with document tabs

## Status

Accepted

Supersedes: [ADR-0006](adr_0006_optional_folder_browsing_mode.md) — Optional folder browsing mode.

## Date

2026-08-29

## Context

ADR-0006 зафиксировал folder browsing как минимальный режим навигации: дерево только с Markdown-файлами, один активный документ, без вкладок, без файловых операций, без watcher, без поиска, без сохранения сессии.

С тех пор фича прошла продуктовую и дизайн-проработку (бандл `design/MD редактор_ файлы и папки.zip`: `README.md` и тринадцать экранов макета). Заказчик принял решения, которые прямо расходятся с ADR-0006:

| Вопрос | Решение заказчика | Статус в ADR-0006 |
|---|---|---|
| Вкладки документов | Да, горизонтальная полоса справа от сайдбара | Rule 4: запрещены |
| Что показывать в дереве | Все файлы, не-документы приглушены | Rule 10: только `.md` / `.markdown` |
| Файловые операции из дерева | Создать / переименовать / удалить / дублировать | Rule 7: out of scope |
| Поиск по именам файлов | Да, в сайдбаре | Non-goal: global folder search |
| Внешние изменения на диске | `FileSystemWatcher` с дебаунсом | Non-goal: file watcher |
| Состояние сессии | Сохраняется (окно, вкладки, ширина сайдбара) | Rule 6: transient, без restore |
| Вторая папка | Новое окно | Не рассматривалось |

Причина изменения решения: сценарий «читаю набор документации» на практике означает «держу рядом два-три документа», а не «читаю строго по одному». Без вкладок каждый переход по ссылке между файлами теряет предыдущий документ и его позицию прокрутки. Это делает режим папки неудобным ровно в том сценарии, ради которого он вводился.

Что **не** изменилось и остаётся обязательным:

- MarkMello — viewer-first, а не IDE и не workspace platform;
- fast path `open file -> readable document` не должен дорожать;
- editor subsystem остаётся ленивой и не участвует в viewer fast path;
- document surface остаётся главным визуальным центром;
- приложение остаётся local-first и file-first, без БД, индекса и project metadata.

ADR-0006 нельзя просто дополнить: он отклоняет вкладки как Alternative A и объявляет их non-goal. Поэтому он заменяется целиком.

## Decision

MarkMello получает **folder workspace mode**: явно открытая локальная папка с деревом файлов в левом сайдбаре и открытыми документами во вкладках.

Это по-прежнему **вторичный режим поверх file-first viewer**, а не новая основная модель приложения. Ограничения ниже — то, что удерживает его от превращения в IDE.

## Rules

### 1. Single-file fast path неприкосновенен

Открытие одного файла из CLI, file association, picker'а или drag&drop:

- не создаёт folder session;
- не создаёт sidebar;
- не инстанцирует workspace-подсистему (`WorkspaceViewModel` и всё, что за ним);
- не обходит директории и не строит индексов;
- не запускает watcher.

`ShowsSidebar` вычисляется из наличия workspace, а не наоборот. Регресс-тест на это обязателен (см. Rule 12).

Если folder mode ухудшает single-file fast path — реализация считается неверной независимо от удобства новой функции.

### 2. `Open Folder` — только явное действие

Entry points: пункт меню приложения, кнопка на welcome-экране, `Ctrl Shift O` (на macOS `⌘⇧O`), drag&drop каталога, аргумент командной строки-каталог.

Аккорды не используются: инфраструктуры аккордов в приложении нет, а состояние ожидания второй клавиши потребовало бы нового chrome. `Ctrl Shift O` свободен в текущих `Window.KeyBindings`.

Недопустимо:

- делать folder mode режимом по умолчанию;
- превращать welcome в project launcher;
- автоматически открывать родительскую папку файла как workspace.

Открытие папки не открывает документ автоматически, кроме одного исключения: если в корне есть `README.md`, он открывается первой вкладкой. Иначе — пустое состояние document surface.

### 3. Sidebar существует только в folder mode

- не монтируется в визуальное дерево single-file режима;
- сворачивается пользователем (папка при этом остаётся открытой);
- закрывается вместе с folder session командой «Закрыть папку», которая возвращает приложение в обычный single-file / welcome shell;
- ширина 260px по умолчанию, диапазон 220–340 через `GridSplitter`, значение сохраняется.

### 4. Вкладки разрешены и ограничены

Вкладки — это **список открытых документов**, а не multi-document editor.

В scope:

- горизонтальная полоса вкладок внутри контентной области, справа от сайдбара;
- активация, закрытие (крестик, `Ctrl W`, средний клик), меню переполнения «ещё N»;
- вкладка хранит свою позицию прокрутки и восстанавливает её при активации;
- вкладка принадлежит workspace (`BelongsToWorkspace = true`) либо является файлом, открытым поверх папки — такие в дереве не подсвечиваются;
- dirty-state переиспользует существующий диалог «Сохранить / Не сохранять / Отмена», поднятый с уровня окна на уровень вкладки.

Вне scope:

- split view из двух документов одновременно;
- вертикальные вкладки, группы вкладок, закрепление;
- вкладки для не-документов (настройки, диаграммы, превью).

Одновременно активен ровно один документ. Полоса вкладок не должна становиться постоянным chrome: без открытых вкладок её нет.

### 5. Дерево ленивое

- при открытии папки читается только корневой уровень;
- содержимое поддиректории читается при первом раскрытии;
- Markdown не парсится до открытия конкретного файла;
- повторное раскрытие может использовать in-memory cache в рамках сессии.

Запрещено: full recursive scan, построение индекса, предварительный подсчёт outline / word count по папке, фоновые обходы дерева.

### 6. Дерево показывает все файлы, открываются — только поддерживаемые

- показываются директории и все файлы;
- файлы поддерживаемых типов (`SupportedDocumentTypes`: `.md`, `.markdown`, `.txt`) отображаются обычным цветом текста и открываются во вкладке;
- документ открывают левый клик по строке и `Enter`; правый клик и навигация стрелками только выделяют строку;
- остальные файлы приглушены и **инертны**: клик выделяет строку, но не открывает документ и не передаёт файл в markdown pipeline;
- служебные каталоги (`.git`, `node_modules`, `bin`, `obj`) и скрытые элементы скрыты; список — константа реализации, UI-переключателя в первой версии нет;
- сортировка: сначала каталоги, потом файлы, `StringComparer.OrdinalIgnoreCase`.

### 7. Файловые операции разрешены в минимальном наборе

In scope: создать файл, создать папку, переименовать (`F2`), удалить (`Del`, с подтверждением), дублировать, показать в файловом менеджере ОС.

Вне scope: перемещение и drag-and-drop reorder в дереве, копирование между папками, массовые операции, собственный undo файловых операций, git-действия.

Требования:

- операция выполняется над реальной файловой системой немедленно, промежуточного «проекта» нет;
- **удаление идёт в корзину ОС**, а не безвозвратно: это снимает потребность в собственном undo. Требуется абстракция в Application и три платформенные реализации (Windows — `IFileOperation` / `SHFileOperationW`, macOS — `NSFileManager trashItem`, Linux — freedesktop trash spec). Там, где корзина недоступна (сетевой путь, отключённая корзина, отсутствие `~/.local/share/Trash`), операция либо отменяется, либо выполняется безвозвратно с явно изменённым текстом подтверждения — молчаливого безвозвратного удаления быть не должно;
- открытые вкладки переименованного файла обновляют заголовок; удалённого — закрываются;
- ошибка операции (нет прав, файл занят, имя занято) показывается локально и не ломает ни дерево, ни document surface;
- «показать в файловом менеджере» требует расширения `IPlatformServices` — платформенная команда, а не `Process.Start` из Presentation.

### 8. Поиск — только по именам и только в рамках открытой папки

- фильтрация по подстроке имени, без чтения содержимого файлов;
- выполняется в фоне с `CancellationToken`, предыдущий запрос отменяется на каждое нажатие;
- ограничения по глубине и числу просмотренных записей; при достижении лимита выдача считается неполной, и это должно быть видно пользователю;
- `Esc` сбрасывает.

Полнотекстовый поиск по папке, индекс, backlinks и project-wide diagnostics остаются non-goals.

### 9. Watcher разрешён, но только после открытия папки

- `FileSystemWatcher` создаётся вместе с folder session и уничтожается вместе с ней; в startup path его нет;
- дебаунс 250 мс, диспетчеризация в UI-поток;
- обновляет дерево; влияние внешних изменений на открытые вкладки (внешнее удаление, переименование, изменение содержимого) должно быть определено явно и не должно молча терять несохранённые правки;
- сбой watcher (нет прав, сетевой путь, переполнение буфера) деградирует до «дерево не обновляется автоматически», а не до падения окна.

### 10. Состояние сессии сохраняется на уровне окна, но не воскрешает папку само

- сохраняются глобально: ширина сайдбара и настройки чтения;
- состав вкладок, активная вкладка и раскрытые узлы принадлежат окну;
- при холодном старте без аргументов приложение **не** открывает автоматически последнюю папку — стартовое поведение single-file / welcome не меняется;
- новые поля настроек обязаны быть зарегистрированы в `MarkMelloJsonSerializerContext`, иначе publish-сборка падает в рантайме.

Persistent workspace file (`.markmello`, `.workspace`), БД и project metadata по-прежнему не создаются.

### 11. Вторая папка — новое окно

Одна папка = одно окно. Multi-root workspace не вводится.

- настройки чтения и темы общие для окон;
- состав вкладок и folder session — на окно;
- `ShutdownMode = OnLastWindowClose`;
- закрытие окна с грязными вкладками проходит по ним последовательно через существующий диалог.

### 12. Производительность измеряется, а не декларируется

Минимальный набор метрик, снимаемый через `IStartupMetrics` и локальное профилирование:

- startup time, time to first window, time to readable document — в single-file сценарии;
- `Open Folder` activation time, root load time, expand directory time;
- memory usage: single-file viewer / после открытия папки / после раскрытия крупной директории.

Правило приёмки: baseline снимается **до** M1 на текущем `main`; ни один из single-file показателей не должен ухудшиться относительно baseline за пределами шума измерения. Абсолютные бюджеты для folder-операций фиксируются по результату baseline-замера и вносятся в implementation plan, а не выдумываются заранее.

Обязательный регресс-тест: `WorkspaceViewModel` не создаётся при старте с одним файлом.

### 13. Открытие документа переиспользует общий pipeline

Файл из дерева и файл из вкладки открываются тем же `OpenDocumentUseCase`, что и обычный `Open File`. Отдельного folder-specific loader'а нет, editor mode не становится зависимостью folder mode, viewer-возможности (диаграммы, изображения, document-wide selection, find) работают одинаково.

### 14. Ошибки folder mode локальны

Папка удалена, нет прав на поддиректорию, файл исчез между построением дерева и открытием, директория слишком большая — всё это показывается в соответствующем узле дерева или в document surface. Окно продолжает работать, пользователь может выбрать другой файл.

## Architecture impact

### Domain

`WorkspaceFolder`, `WorkspaceEntry`, `OpenDocumentTab`, `WorkspaceSessionState`. Без зависимостей от Avalonia и editor subsystem. `IsSupportedDocument` вычисляется существующим `SupportedDocumentTypes.IsSupportedPath`.

### Application

- `IFilePicker.PickFolderAsync`;
- `IWorkspaceFileSystem` — enumerate / create / rename / delete / search;
- `IWorkspaceWatcher`;
- расширение `IPlatformServices` — reveal in file manager;
- use cases `OpenFolderUseCase`, `ExpandFolderNodeUseCase`, `SearchWorkspaceFilesUseCase`;
- `OpenDocumentUseCase` / `SaveDocumentUseCase` не меняются.

### Infrastructure

`DirectoryWorkspaceFileSystem` на `Directory.EnumerateFileSystemEntries`, `FileSystemWorkspaceWatcher`, поиск в `Task.Run` с лимитами, новые поля в `SettingsFileModel` плюс регистрация в source-gen контексте.

### Presentation

- `ShellViewModel` — облегчённый текущий `MainWindowViewModel`: тема, оверлеи, настройки чтения, статус-бар, drag&drop, заголовок окна;
- `WorkspaceViewModel` — создаётся только при открытии папки;
- `FileTreeNodeViewModel`, `OpenDocumentsViewModel`, `DocumentTabViewModel`;
- `WorkspaceSidebarView`; полоса вкладок — `ItemsControl` плюс один `ContentControl`, **не** `TabControl` (он пересоздаёт контент и теряет прокрутку `MarkdownDocumentView`);
- дерево — `TreeView` и `HierarchicalDataTemplate` с `x:DataType`; `TreeDataGrid` не подключается;
- новые стили — в `Themes/Controls.axaml`; новых **цветов** в `Colors.axaml` не добавляется. Вводится один новый **ключ** `MmTreeInertTextBrush` на существующих значениях палитры — light `#6F6A65`, dark `#A29E98`: `MmTextFaintBrush` даёт для 12.5px строки дерева 3.2:1 в светлой теме и 3.5:1 в тёмной;
- локализация: `TreeRevealInExplorer` — три ключа с выбором по `IPlatformServices.PlatformName`; счётчик в подвале сайдбара требует форм множественного числа, которых плоский словарь не даёт;
- мультиокно требует пересмотра DI: `MainWindow`, `MainWindowViewModel` и `Func<TopLevel?>` сейчас синглтоны, привязанные к `lifetime.MainWindow`.

## Rejected alternatives

### A. Оставить ADR-0006 как есть

Отклонено: переход по ссылке между документами теряет предыдущий документ и его прокрутку; режим папки перестаёт решать сценарий, ради которого вводился.

### B. Multi-root workspace в одном окне

Отклонено: требует project-модели и постоянной панели проектов — прямой путь к IDE. Новое окно решает сценарий дешевле.

### C. `TabControl` для полосы вкладок

Отклонено по технической причине: пересоздание контента при переключении сбрасывает `MarkdownDocumentView` и позицию прокрутки.

### D. Persistent workspace file и автооткрытие последней папки

Отклонено: делает folder mode частью startup path и нарушает Rule 1.

### E. Полнотекстовый поиск по папке

Отклонено: требует индекса и фонового обхода, что запрещено Rules 5 и 8.

## Consequences

### Positive

- сценарий чтения набора документации закрывается полностью;
- single-file fast path остаётся защищённым явными правилами и регресс-тестом;
- ограничения (один активный документ, без split view, без multi-root, без индекса) удерживают продукт от дрейфа в IDE.

### Neutral

- shell state усложняется: workspace плюс вкладки плюс сессия окна;
- `MainWindowViewModel` (1744 строки) требует разделения на `ShellViewModel` и подсистемы вкладок — самый рискованный рефакторинг фичи;
- часть UX-решений уточняется в дизайн-задании и implementation plan без изменения этого ADR.

### Negative

- мультиокно требует переработки DI-регистраций Presentation;
- файловые операции и watcher добавляют классы ошибок, которых у viewer'а раньше не было;
- растёт поверхность для регрессов производительности — отсюда обязательные замеры.

## Implementation sequence

Детализация — [implementation-plan-folders-tabs.md](../implementation-plan-folders-tabs.md).

1. **M0** — baseline-замеры на текущем `main` (Rule 12).
2. **M1** — домен, `OpenFolderUseCase`, `PickFolderAsync`, сайдбар только для чтения; одна вкладка, как сейчас.
3. **M2** — вкладки: `DocumentTabViewModel`, `OpenDocumentsViewModel`, полоса, «ещё N», грязные вкладки.
4. **M3** — поиск, файловые операции, контекстное меню, watcher.
5. **M4** — сессия окна, второе окно, CLI-аргумент каталога, контрольные замеры.

Переход к следующему этапу — только после замеров предыдущего.

## Final statement

```text
Open local folder -> lazily browse files -> keep a few documents in tabs -> read
```

MarkMello остаётся быстрым local-first Markdown viewer с опциональным edit mode. Папка — это временный контекст навигации, вкладки — список открытых документов, и ни то, ни другое не является главной концепцией продукта.
